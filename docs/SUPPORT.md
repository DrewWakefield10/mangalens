# Feature support in this release

See the [latest reliability report](RELIABILITY-2026-10-20.md) for OCR, cleanup recovery, API-budget fixes and restart instructions.

“Implemented” means a working code path, not a guarantee of translation accuracy. The CC0 Japanese fixture and user-supplied manga pages are exercised with real CPU inference. This is a functional check, not an independently scored translation-accuracy benchmark.

The UI only exposes capabilities that have code paths. Unconfigured providers are labeled; missing language pairs, missing fonts and OCR failures return errors. Future capabilities above are documented instead of represented by fake buttons or simulated results.

The editor's numbered debug boxes now distinguish completed, OCR, translation, cleanup and rendering failures. Selecting a box reveals its stable region ID, classification, source and translation, stage history, and failure reason. Cloud-only OCR can receive a DeepL suggestion for review, but text without a safe bubble mask is not erased automatically. A short Japanese interjection or an alternate OCR reading that changes the referent stays original until the user verifies the wording. A page reports partial completion whenever a meaningful candidate remains unresolved; the counters describe detected, recognized, translated, cleaned and rendered regions separately. These checks do not prove that all text on an image was detected.

The Mask view shows only the pixels actually used to remove lettering from the current Clean image. A region can have a nonempty **candidate** mask and zero **applied** pixels when OCR, translation, placement, or artwork safety still needs review. The editor reports both counts. Clean and Translated images are published for the same completed page revision; generated image requests during processing or for a stale revision are rejected. Retrying a single mask or cleanup reuses unchanged regions' cleaned pixels and never calls OCR.space or DeepL.

The local OCR decision thresholds can be configured with `OCR_MIN_CONFIDENCE` (default `0.7`) and `OCR_MIN_AGREEMENT` (default `0.85`). OCR.space confidence remains unavailable; changing these settings does not create a confidence score for its responses.

Offline availability is checked per direction, not just per provider. The health API and Settings list completely installed pairs, the import dialog labels missing choices, and explicit missing pairs are rejected before jobs start (including retries). Auto-detected source languages are checked during inference. A configured external fallback may handle a missing offline pair. The default setup still installs Japanese → English. `scripts/setup_models.py --all-app-languages` installs every published direct pair among the app languages, including both SentencePiece and Moses/BPE packages; `scripts/check_models.py` checks each installed pair with real CPU inference. Installation and inference reports are saved in `models/`.

This workspace has all 28 published direct pairs for the app's languages installed. These cover English in both directions with the other 13 languages, plus Spanish ↔ Portuguese. Other combinations require a configured provider; automatic pivot translation is not implemented. Spanish → English uses CPU float32 because its published model produced repeated output under int8 in local inference checks. The short inference check confirms execution, not translation accuracy or OCR coverage.
